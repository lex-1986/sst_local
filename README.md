# SST Local (MCS350)

Неофициальная интеграция Home Assistant для **локального** управления терморегуляторами
SST / Теплолюкс **MCS350** — без облака SST Cloud.

Интеграция общается с терморегулятором напрямую по TCP (порт 6350) тем же протоколом,
которым пользуется приложение SST Cloud при добавлении устройства. Облако, аккаунт и
интернет не нужны — достаточно, чтобы Home Assistant видел терморегулятор в сети.

Актуально в связи с закрытием SST Cloud: облачная интеграция
[sst_cloud](https://github.com/sergeylysov/sst_cloud) перестаёт работать при переходе на ATLAS.

## Возможности

Для каждого терморегулятора создаётся устройство с сущностями:

| Сущность | Описание |
|---|---|
| `climate` | Режимы: **Выкл**, **Нагрев** (ручной), **Авто** (по расписанию). Пресет **«Не дома»** — режим «Отпуск». Уставка температуры. |
| Температура пола | Датчик пола, °C |
| Температура воздуха | Встроенный датчик воздуха, °C |
| Время работы нагрева | Счётчик наработки реле нагрева, ч |
| Уровень Wi-Fi | 0–4, диагностический |
| Нагрев | Включено ли реле нагрева сейчас |
| Ошибка датчика пола | Обрыв / неисправность выносного датчика |

Поведение `climate`:

- **Нагрев** — ручной режим, уставка 12–45 °C.
- **Авто** — работа по расписанию, записанному в терморегуляторе; уставка показывает
  температуру текущей точки расписания. Если задать температуру в режиме «Авто»,
  терморегулятор перейдёт в ручной режим с этой уставкой.
- **Не дома** — режим «Отпуск», уставка 5–12 °C.
- Атрибуты: `temperature_manual`, `temperature_vacation`, `temperature_chart`,
  `temperature_air_limit`, `schedule` (всё расписание).

Опрос — каждые 30 секунд.

## Расписание автоматического режима

В режиме **Авто** терморегулятор работает по недельному расписанию, которое хранится
в нём самом: **4 точки на каждый день**. Каждая точка — время и температура, которая
действует с этого времени до следующей точки (после последней точки дня — до первой
точки следующего дня). Время точек внутри дня должно идти по возрастанию,
температура — 0–45 °C.

### Редактирование в интерфейсе

На странице устройства, в разделе **Настройки**:

| Сущность | Назначение |
|---|---|
| Расписание: день | Какой день недели показывать и редактировать |
| Расписание: точка 1–4, время | Время начала точки выбранного дня |
| Расписание: точка 1–4, температура | Температура точки выбранного дня |
| Расписание: копировать на будни | Скопировать выбранный день на пн–пт |
| Расписание: копировать на все дни | Скопировать выбранный день на всю неделю |

Изменение сразу записывается в терморегулятор.

### Сервисы

`sst_local.set_schedule` — записать расписание сразу для нескольких дней:

```yaml
action: sst_local.set_schedule
target:
  entity_id: climate.vanna
data:
  days: [mon, tue, wed, thu, fri]
  points:
    - {time: "06:00", temperature: 28}
    - {time: "09:00", temperature: 18}
    - {time: "18:00", temperature: 28}
    - {time: "23:00", temperature: 18}
```

Дни: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`. Точек — ровно 4, порядок не важен
(они сортируются по времени).

`sst_local.get_schedule` — вернуть текущее расписание (ответ сервиса):

```yaml
action: sst_local.get_schedule
target:
  entity_id: climate.vanna
response_variable: schedule
```

Ответ: `{"mon": [{"time": "06:00", "temperature": 28}, ...], "tue": [...], ...}`.

## Требования

- Home Assistant 2025.2 или новее.
- Терморегулятор подключён к Wi-Fi (настроен ранее через приложение SST Cloud).
- Home Assistant может достучаться до терморегулятора по TCP-порту **6350**.
- Желательно закрепить за терморегулятором постоянный IP в DHCP роутера.

IP-адрес можно найти в списке DHCP-клиентов роутера: MAC-адреса MCS350
начинаются на `D8:A0:1D` (модуль Espressif).

## Установка

### HACS (пользовательский репозиторий)

1. HACS → три точки справа сверху → **Пользовательские репозитории**.
2. Репозиторий `https://github.com/lex-1986/sst_local`, категория **Интеграция** → **Добавить**.
3. Найти **SST Local (MCS350)** и установить.
4. Перезапустить Home Assistant.

### Вручную

1. Скопировать папку `custom_components/sst_local` в `config/custom_components/`.
2. Перезапустить Home Assistant.

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → SST Local (MCS350)**

| Поле | Значение |
|---|---|
| Название | Любое, например «Ванна» |
| IP-адрес | IP терморегулятора |
| Порт | `6350` (по умолчанию) |

Каждый терморегулятор добавляется отдельно. При добавлении интеграция сразу читает
состояние устройства; если связи нет — появится ошибка «Не удалось подключиться».

Можно использовать параллельно с облачной `sst_cloud`.

## Протокол

Описание для тех, кто захочет доработать или проверить.

Кадр:

```
0x02 'T' <dir> <cmd> <len: u16 BE> <payload> <crc: u16 BE>
```

- `dir` — `Q` в запросе клиента, `A` в ответе устройства.
- `cmd` — `R` чтение конфигурации, `W` запись. В ответе на запись на месте `cmd`
  стоит код результата: `0x00` — успешно.
- CRC — CRC-16/CCITT-FALSE (poly `0x1021`, init `0xFFFF`) по всему кадру без CRC.
- `payload` — последовательность блоков TLV: `<тег: 1 байт ASCII> <длина: u16 BE> <значение>`.

Чтение: `02 54 51 52 00 00 <crc>` → ответ `02 54 41 52 <len> <TLV...> <crc>`.

Блоки ответа MCS350:

| Тег | Содержимое |
|---|---|
| `T` | t° пола (signed, `-127` — ошибка датчика), t° воздуха, день недели (0 = пн), индекс текущей точки расписания |
| `S` | вкл/выкл, режим (0 ручной, 1 расписание, 2 отпуск), биты датчиков (bit0 воздух, bit1 пол), уставка ручная, уставка отпуск, лимит t° воздуха, коррекция t° воздуха |
| `C` | расписание: 7 дней × 4 точки × (минуты от полуночи u16, t°) |
| `H` | реле нагрева (1 — греет) |
| `L` | наработка реле: часы u16, минуты |
| `W` | уровень Wi-Fi |
| `O` | минуты режима «открытое окно» |
| `I` | тип устройства (2 символа) и версия прошивки (3 символа) |
| `M` | MAC-адрес строкой |
| `A`, `Z`, `D` | доступ, выбор датчика, время устройства (unix) |

Запись настроек — блок `S` из 7 байт:

```
02 54 51 57 00 0A  53 00 07  <status> <mode> <sensors> <t_manual> <t_vacation> <t_air_limit> <t_air_corr>  <crc>
```

Запись расписания — блок `C` из 84 байт (всегда вся неделя):

```
02 54 51 57 00 57  43 00 54  28 × (<минуты от полуночи: u16 BE> <t°>)  <crc>
```

Порядок точек: пн 1–4, вт 1–4, …, вс 1–4.

Терморегулятор обслуживает одно TCP-соединение за раз; при одновременном обращении
другого клиента запрос может не получить ответа — интеграция повторяет его один раз.

> **Внимание.** Команда `W` также принимает блоки `W`/`P` (SSID и пароль Wi-Fi), `M` (адрес
> MQTT-сервера) и `U` (идентификатор дома) — их отправка может отключить терморегулятор
> от сети или облака. Интеграция их не использует.

## Ограничения

- Проверено на MCS350 с прошивкой 3.1.9. Другие модели SST (MCS300, Equation,
  EcoSmart 25, OKE-20) используют тот же транспорт, но другой формат блоков — не поддерживаются.
- Лимит и коррекция температуры воздуха пока только читаются; их можно менять на самом
  терморегуляторе.
